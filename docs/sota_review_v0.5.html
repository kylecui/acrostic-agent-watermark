2. 关键洞察 转折点

① 签名 = 防篡改 + 溯源，二者所需不同
防篡改需 binding（脆而严）；溯源需 recovery（鲁棒而松）。SOTA 无人同时做好两者——这是空位。
② 位置绑定是 v0.3/v0.4 根本瓶颈
锚点 SHA256(left‖self‖right) 依赖相邻词身份不变。PostMark/SimMark/中文零水印的共同突破：不绑定位置，靠全文统计分布。
③ 你的"向量点积"直觉有密码学根基
Collab Threshold §4.3 明确：
⟨θ_s, τ⟩ = Σ_i λ_i · ⟨θ_s, s_i⟩
检测统计量 = 嫌疑对象与密钥向量的内积，且可 Shamir 分片分解。KGW 的 0/1 绿名单向量内积是其特例。
④ 纪昀"也字勾" = 中文零水印（17年学术积淀）
王晓龙 2009：统计汉字频次→提取高频序→注册IPR库→相关函数检测。
即"不固定位置、高频、语义必需、靠次数冗余"。弱点：需中心化 IPR 库。

3. 统一内积框架 点积视角

把全文特征组织成向量 v(text)，UID 编码成密钥向量 τ_uid，检测 = 内积 + z 检验。

v(text) = [绿名单词频, 声母频次, 句嵌入相似度序列, ...]
τ_uid = 密钥 K + UID 派生的区间指示向量
score = ⟨v(text), τ_uid⟩ = Σ_j v_j(text) · τ_j
z = (score - μ_null) / σ_null
detect = z > β ⟹ UID = argmax_uid ⟨v, τ_uid⟩
现有方案在该框架下的特例
KGWv = 0/1 绿名单指示向量，τ = 全1
PostMarkv = 词频向量，τ = 密钥词表嵌入
SimMarkv = 句相似度区间指示，τ = 区间权重
中文零水印v = 高频词序特征，τ = 注册指纹

4. 推荐路线：双信道签名架构 v0.5 综合 · 互补弱点

信道 A：Tamper Binding（防篡改）

脆而严 · 密码学 binding · paraphrase 即失效（设计意图）
H = HMAC-SHA256(key, normalize(text))
或 Merkle(段落级) 可定位篡改位置
保证：PRF 假设下不可伪造
用途：判"这段文本是否被改过"
借鉴：Collab Threshold 的 commitment scheme

信道 B：Provenance Recovery（溯源）

鲁棒而松 · 全文统计 · 不绑定位置 · 承载 16-bit UID
G = { w | top-bit HMAC(K, w) ∈ target(UID) }
嵌入: post-hoc 同义替换让绿名单词占比 ∈ [p_uid, p_uid+Δ]
检测: z = (|G∩text|/N - p_0) / σ_0 ⟹ 反查 UID
保证：不知 K 无法构造落入区间的分布
用途：从被改文本恢复"谁生成"
借鉴：KGW 绿名单 + PostMark 全文统计 + 中文零水印高频
⇅ 协同 ⇅
文本未改 → A ✓ + B ✓ 双重确认 + UID
文本被改 → A ✗ 报篡改，B 仍尽力溯源 UID（鲁棒冗余）
伪造攻击 → 不知 K，无法同时满足 HMAC binding + 绿名单区间
