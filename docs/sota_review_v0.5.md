## 2. 关键洞察

### 2.1 签名 = 防篡改 + 溯源，二者所需不同
- **防篡改**需要 **binding**（绑定特定内容/时刻）：commitment scheme、HMAC、Merkle 树。任何内容改动使签名失效。
- **溯源**需要 **recovery**（从被改文本恢复 UID）：冗余编码、扩频、统计检验。允许内容受损仍能提取。
- **二者张力**：防篡改越严格 → 越脆；溯源越鲁棒 → 越易被伪造。SOTA 无人同时做好两者。

### 2.2 位置绑定是 v0.3/v0.4 的根本瓶颈
- v0.3 锚点 `fp = SHA256(left_stable_id ‖ self_stable_id ‖ right_stable_id)` 依赖**相邻词身份不变**。
- v0.4 句边界感知只解耦了跨句污染，**句内首末词 stable_id 一变即崩**（实验已验证）。
- PostMark/SimMark/中文零水印的共同突破点：**不绑定位置，靠全文统计分布**。

### 2.3 向量点积可分解 —— 你的"X积/点积"直觉有密码学根基
- Collaborative Threshold Watermarking §4.3 明确给出：`⟨θ_s, τ⟩ = Σ_i λ_i ⟨θ_s, s_i⟩`
- 即**检测统计量是嫌疑对象与密钥向量的内积**，且可跨 Shamir 分片分解求和。
- 启示：若把"文本"投影成一个特征向量 `v(text)`，UID 编码成密钥向量 `τ_uid`，则**检测 = ⟨v(text), τ_uid⟩ 的 z 检验**。这正是 KGW 绿名单的推广（KGW 是 0/1 特征向量的特例）。

### 2.4 中文零水印 = 纪昀"也字勾"的学术对应
- 王晓龙 2009：统计汉字频次 → 提取高频序作特征 → 注册到 IPR 库 → 检测用相关函数。
- 这就是"不固定位置、高频、语义必需、靠次数冗余"——你提的纪昀思路已有 17 年学术积淀。
- **弱点**：需 IPR 库注册（中心化），UID 区分度依赖语料。

## 4. 综合路线推荐：双信道签名架构（v0.5）

**核心思想**：一条文本同时承载两个信道，互为冗余、互补弱点。

### 信道 A：Tamper Binding（防篡改，脆而严）
- **载体**：全文规范化后的特征指纹 `H = HMAC(key, normalize(text))` 或 Merkle 化。
- **作用**：任何内容改动 → H 不匹配 → 判定被篡改。
- **密码学保证**：HMAC-SHA256 PRF 假设下不可伪造。
- **弱点**：脆，paraphrase 即失效。这正是其**设计意图**（防篡改本就该脆）。

### 信道 B：Provenance Recovery（溯源，鲁棒而松）
- **载体**：全文用词分布的**密钥派生绿名单统计** z 检验，承载 16-bit UID。
- **机制**（借鉴 KGW 绿名单 + PostMark 全文统计 + 中文零水印高频特征）：
  1. 密钥 `K` 派生绿名单 `G = {w | HMAC(K, w) 的 top-bit ∈ target}`（文本无关，类似 UNIGRAM）
  2. **UID 编码**：16-bit UID → 决定绿名单的**目标比例区间** `[p_uid, p_uid + Δ]`（每个 UID 一个区间）
  3. 嵌入：post-hoc 同义替换，让全文绿名单词占比落入 UID 对应区间
  4. 检测：统计绿名单词数，做 z 检验，反查最可能 UID
- **不绑定位置**：全文聚合，抗剪切/换序/局部替换。
- **弱点**：绿名单可被逆向（需密钥派生抵抗）；单 UID 区分度受文本长度限制。

### 信道协同
- A 脆 B 鲁棒：文本未改 → A+B 都验，双重确认 + UID；文本被改 → A 报篡改，B 仍尽力溯源 UID。
- 伪造攻击：攻击者不知 K，无法构造落入正确区间的用词分布（需大量改写）。

### 与你"向量点积"直觉的对接
信道 B 可进一步泛化为：
- 把全文特征（绿名单词频向量、声母频次向量、句嵌入相似度序列）组织成向量 `v(text)`。
- UID 编码成密钥向量 `τ_uid`（如 one-hot 区间指示或 Shamir 分片）。
- **检测统计量 = ⟨v(text), τ_uid⟩**，z 检验判定。
- 这统一了 KGW（0/1 绿名单向量内积）、PostMark（词频向量内积）、SimMark（相似度区间指示内积）。

## 5. 待用户决策的开放问题

1. **信道 A 的 binding 粒度**：全文 hash（最严，任何字符改即失效）vs 段落级 Merkle（局部篡改可定位）？
2. **信道 B 的绿名单构造**：文本无关密钥派生（抗逆向强但需长文本）vs 文本相关（PostMark 式，短文本友好但依赖 embedding）？
3. **是否引入向量点积形式**：把 B 泛化为 `⟨v(text), τ_uid⟩`，统一框架但实现复杂度上升？
4. **中文路径**：直接用高频声母全文频次向量（纪昀路线）还是走绿名单？
5. **保留 v0.3/v0.4 投票桶作为第三冗余信道？** 还是完全切换到统计检测？
