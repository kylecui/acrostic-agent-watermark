# AAWM 设计文档（草稿 v0.1）

> 状态：起步设计，待评审与迭代

## 1. 设计目标

### 1.1 必须满足
- **G1 黑盒可用**：不依赖 LLM logits / 自定义采样，闭源 API（OpenAI / Anthropic / Google）即可
- **G2 agent 级归属**：水印绑定到 agent 实例（或 agent + 会话），而非底层 LLM
- **G3 语义保持**：变换后输出与原输出语义等价，对人类读者无感知差异
- **G4 可验证性**：持有密钥的验证者能用统计检验判定水印存在，给出 p-value
- **G5 抗推断**：不知密钥的攻击者无法从输出推断水印位置或比特

### 1.2 期望满足
- **G6 鲁棒性**：对轻度 paraphrase / 截断 / 翻译有一定抗性
- **G7 容量**：单条输出可承载 ≥ 16 bit 隐式水印（足以区分 65536 个 agent 实例）
- **G8 低开销**：嵌入耗时 < 原始生成的 10%

### 1.3 不追求
- 强抗重写（重写后语义保留即视为通过）
- 公开可检测（本项目刻意走"密钥验证"路线，不做公开检测）

**核心组件**：

| 组件 | 职责 | 输入 | 输出 |
|---|---|---|---|
| **CandidateGenerator** | 为每个可变 token 位置生成语义等价候选集 | 原始 token + 上下文 | 候选 token 列表 |
| **KeyDerivation** | 用密钥 + 上下文哈希派生锚点位置和谓词参数 | secret_key, context_hash | (positions, predicates) |
| **Embedder** | 在锚点位置选择满足谓词的候选 | 原始文本 + 密钥 + 候选 | 水印文本 |
| **AnchorReconstructor** | 验证者重建锚点位置和谓词 | 嫌疑文本 + 密钥 | (positions, predicates, hits) |
| **StatisticalTest** | z-score / p-value 检验 | 命中数 + 锚点数 | p-value, decision |

## 3. 算法详述

### 3.1 密钥派生

```
master_key: 256-bit secret (agent 实例身份)
session_salt: 64-bit random per session (公开，防跨会话关联)
context_hash: SHA256(前序 token 序列) 前 128 bit

派生：
  anchor_seed = HKDF(master_key, salt=session_salt, info="anchor", context=context_hash)
  predicate_seed = HKDF(master_key, salt=session_salt, info="pred", context=context_hash)
```

### 3.2 锚点位置选择（Anchor Selection）

**目标**：在 N 个 token 中选 k 个锚点，使攻击者无法预测。

**算法**：
1. 对每个 token 位置 $i \in [0, N)$，计算 $h_i = \text{PRF}(\text{anchor\_seed}, i)$
2. 计算可变性分数 $m_i$（该 token 是否有同义候选；见 3.3）
3. 在可变位置集合 $\{i : m_i > 0\}$ 上，按 $h_i$ 排序取前 $k = \lceil \alpha \cdot |\text{mutable}| \rceil$，$\alpha \in [0.1, 0.3]$
4. 排序结果作为锚点集合 $\mathcal{A}$

**为什么按 PRF 排序而非直接 PRF > 阈值**：排序保证锚点数稳定为 k，便于容量估计。

### 3.3 候选生成（Candidate Generation）

**MVP（v0.1）**：词典驱动
- 维护同义词典 `synonyms.json`（基于 WordNet / 同义词词林）
- 对每个 token，若词典中存在 ≥ 2 个同义候选，则标记为可变位置
- 候选集合 $C_i = \{c_i^{(1)}, c_i^{(2)}, \ldots\}$

**v0.2**：LLM 再生成
- 对原始输出做 mask-and-regenerate：mask 锚点 token，让 LLM 重新生成 N 个候选
- 用 embedding 相似度过滤，保留语义等价候选

**v0.3**：混合
- 词典覆盖低频词，LLM 覆盖高频 + 领域词

### 3.4 谓词设计

**谓词形式**：$P: \text{token} \times \text{predicate\_params} \to \{0, 1\}$

**候选谓词族**（MVP 用前两个）：

| ID | 谓词 | 参数 | bit/锚点 | 鲁棒性 | 备注 |
|---|---|---|---|---|---|
| P1 | 首字母在 A-M | 无 | 1 | 高 | 字母级，抗 token 化变化 |
| P2 | 词长奇偶 | 无 | 1 | 中 | 词长稳定，但同义词长可能都相近 |
| P3 | hash(token) mod 2^k < 2^(k-1) | k | k | 低 | 高容量但易被推断 |
| P4 | embedding(token) · v > 0 | v (向量) | 1 | 中 | 语义谓词，需 embedding 模型 |
| P5 | token 词性 ∈ {NOUN, VERB} | 无 | 1 | 高 | 句法稳定 |

**谓词选择原则**：
- **可验证性**：验证者能从嫌疑文本重新计算
- **抗推断**：不知密钥时，谓词满足率应接近 0.5（随机）
- **语义保持**：谓词在候选集内总能找到满足项（否则放弃该锚点）

### 3.5 嵌入流程

```
function Embed(original_text, master_key, session_salt):
    tokens = tokenize(original_text)
    candidates = CandidateGenerator(tokens)        # 每位置候选集
    mutable = [i for i in range(len(tokens)) if len(candidates[i]) >= 2]
    
    anchor_seed = HKDF(master_key, session_salt, "anchor", context_hash(tokens))
    anchors = select_anchors(mutable, anchor_seed, alpha=0.2)
    
    watermarked = tokens.copy()
    for pos in anchors:
        pred_params = derive_predicate(HKDF(master_key, session_salt, "pred", pos))
        cands = candidates[pos]
        chosen = None
        for c in cands:
            if P(c, pred_params) == 1:
                chosen = c
                break
        if chosen is None:
            # 候选都不满足，放弃此锚点（不计入命中）
            continue
        watermarked[pos] = chosen
    
    return detokenize(watermarked), metadata(anchors, hits)
```

### 3.6 验证流程

```
function Verify(suspect_text, master_key, session_salt):
    tokens = tokenize(suspect_text)
    candidates = CandidateGenerator(tokens)   # 验证者也需要候选生成能力
    mutable = [i for i in range(len(tokens)) if len(candidates[i]) >= 2]
    
    # 注意：验证者重算锚点时，context_hash 可能因变换而不同
    # 解决：用滑动窗口的局部 context_hash，而非全局
    
    anchor_seed = HKDF(master_key, session_salt, "anchor", context_hash(tokens))
    anchors = select_anchors(mutable, anchor_seed, alpha=0.2)
    
    hits = 0
    valid_anchors = 0
    for pos in anchors:
        pred_params = derive_predicate(HKDF(master_key, session_salt, "pred", pos))
        if P(tokens[pos], pred_params) == 1:
            hits += 1
        valid_anchors += 1
    
    # z-test under H0: hits ~ Binomial(valid_anchors, 0.5)
    z = (hits - 0.5 * valid_anchors) / sqrt(0.25 * valid_anchors)
    p_value = 1 - Phi(z)
    return p_value, hits, valid_anchors
```

### 3.7 关键设计问题：锚点重建的一致性

**问题**：嵌入时和验证时的 context_hash 输入不同（因为 token 已被替换），会导致锚点集合不一致。

**解决方案（MVP）**：
- **不使用全局 context_hash**，改用**位置局部指纹**：`local_hash(pos) = PRF(master_key, pos, session_salt)`
- 锚点选择只依赖位置索引和 mutable 集合，不依赖具体 token 内容
- **代价**：攻击者若知道算法，可以推断锚点位置（但不知谓词参数）
- **缓解**：谓词参数仍由 master_key 派生，攻击者无法伪造满足

**v0.2 改进**：引入轻量上下文绑定（如句首 token 的 hash）+ 容错匹配（允许锚点偏移 ±1）。

## 4. 威胁模型

### 4.1 攻击者能力分级

| 级别 | 能力 | 目标攻击 |
|---|---|---|
| A0 | 仅看到输出文本 | 被动观察 |
| A1 | 知道有水印算法，不知密钥 | 推断水印位置 |
| A2 | A1 + 可 paraphrase | 移除水印 |
| A3 | A2 + 可替换 token | 伪造/嫁祸 |
| A4 | 持有密钥（内部威胁） | 伪造任意 agent 输出 |

### 4.2 防御目标

- **对 A0/A1**：完全不可检测（谓词满足率 ≈ 0.5）
- **对 A2**：轻度 paraphrase 后仍可验证（z-score 衰减但显著）
- **对 A3**：替换 token 难以伪造满足（需猜中锚点 + 谓词，每锚点 1/2^k 概率）
- **对 A4**：超出本方案范围（需结合密码学签名，见 research_notes 1.4）

### 4.3 已知限制
- **平台清洗**：社交媒体平台可能清洗零宽字符（路线 B 失效）→ 本项目主走路线 A，不依赖特殊字符
- **重写攻击**：强 LLM paraphrase 会破坏锚点 → 通过多锚点冗余 + 句首谓词（P1）缓解
- **多 agent 共谋**：多个持密钥 agent 可联合伪造 → 需密钥管理策略（未来工作）

## 5. 容量分析

**每锚点 bit 数**：取决于谓词
- P1/P2/P5：1 bit/锚点
- P4：1 bit/锚点
- P3：k bit/锚点（但鲁棒性差）

**典型场景**：
- 500 token 输出，可变率 30%，锚点比例 α=0.2 → 30 锚点
- P1：30 bit → 可区分 $2^{30} \approx 10^9$ 个 agent 实例
- 检测：z-score = $(30 \cdot 0.8 - 15) / \sqrt{7.5} \approx 4.0$ → p < 0.0001（TPR@1%FPR 充足）

**与 StealthInk 对比**：StealthInk 在 ~300 token 嵌入 ~30 bit（ICML 2025 报告），本项目目标相近但走 agent 后处理路径。

## 8. 开放问题

1. **候选生成质量**：词典覆盖度不足时，可变率过低，锚点稀疏 → 是否引入 LLM 再生成作为兜底？
2. **语义等价保证**：同义词替换可能改变语气/语域（如"big" → "large" → "substantial"）→ 是否需要风格敏感的候选过滤？
3. **多语言**：中文同义词典质量、token 化差异 → 是否先聚焦英文 MVP？
4. **agent 身份绑定**：master_key 如何与 agent 实例绑定？是否需要 KMS / HSM？
5. **可组合性**：多个 agent 嵌套调用时，水印如何叠加？（子 agent 输出被父 agent 嵌入两层水印？）

## 9. MVP 验证结果（2026-08-17）

骨架已跑通端到端流程，在 ~80 词样本上：

| 场景 | z-score | p-value | hits/total | 检出 |
|---|---|---|---|---|
| 持密钥 + hit_positions | 2.65 | 0.004 | 7/7 | ✓ |
| 错密钥 + hit_positions | -0.38 | 0.65 | 3/7 | ✗ |
| 无水印原文 + hit_positions | 0.38 | 0.35 | 4/7 | ✗ |

**四个核心性质全部满足**：可嵌入、可验证、密钥敏感、对无水印文本不误报。

### 9.1 已知限制（v0.1）

- **词典覆盖不足**：占位同义词典仅 ~20 词族，导致 16 个候选锚点中只有 7 个能实际嵌入（43% 命中率）。真实部署需接入 WordNet / 同义词词林 / LLM 再生成。
- **hit_positions 元数据依赖**：当前精确验证模式依赖嵌入端公开 hit_positions。这泄露了"哪些位置被打过水印"，攻击者可针对性攻击这些位置。
  - **缓解**：v0.2 改用"位置局部指纹 + 容错匹配"，让验证者能从嫌疑文本自身重算锚点，无需嵌入端提供 hit_positions。
- **谓词单一**：仅实现 FirstLetterPredicate（A-M / N-Z），容量 1 bit/锚点。需要扩展谓词族（P2-P5）提升容量。
- **分词简陋**：用空白正则分词，未处理标点粘连、缩写、多语言。需接入真实 tokenizer（如 tiktoken / sentencepiece）。
- **未评测鲁棒性**：尚未测试 paraphrase / 截断 / 翻译后的检测衰减。

### 9.2 下一步优先级

1. **高**：扩词典（接入 WordNet）或 LLM 候选生成，把命中率提到 70%+
2. **高**：实现"无 hit_positions"的降级验证（位置局部指纹 + 容错）
3. **中**：扩展谓词族（P4 语义谓词 + P5 词性谓词）
4. **中**：接入真实 tokenizer
5. **低**：鲁棒性评测（与 KGW / Acrostics ICW 对比）

## 10. v0.2：用户 ID 编码（decode 模式，2026-08-18）

> 需求升级：水印不仅要"检测存在"，还要**解码还原出用户 ID**——
> agent 为不同用户生成的输出携带不同的水印，泄露溯源到人。

### 10.1 从"检测导向"到"编码导向"

| 维度 | v0.1 detect 模式 | v0.2 decode 模式 |
|---|---|---|
| 回答的问题 | "有水印吗？" | "这是给哪个用户的水印？" |
| 载荷 | 0 bit（存在性） | 16 bit 用户 ID + 8 bit CRC |
| 锚点携带 | 密钥决定谓词，命中即证据 | 密钥决定字母映射，读出 codeword 位 |
| 判定机制 | z-test 统计显著 | CRC-8 校验 + 纠错码 |
| 误报率 | α（可配置） | 2^-8 ≈ 0.4%（CRC 决定） |

### 10.2 编码流水线

```
嵌入端：
  user_id (16 bit)
    → + CRC-8 (8 bit) = payload (24 bit)          [coding.build_payload]
    → 信道编码 = codeword (72 bit, spread3)         [coding.SpreadRepetitionCode]
    → 锚点 i 携带 codeword[i]
    → KeyedLetterMap(key, salt, pos_i) 反查目标字母集
    → 同义组内选首字母 ∈ 目标集的词

解码端（严格对称）：
  重算可表达锚点池 → 逐锚点 KeyedLetterMap 读 bit
    → codeword (72 bit)
    → 信道解码（纠错） → payload (24 bit)
    → CRC-8 校验 → user_id
```

### 10.3 KeyedLetterMap（密钥符号映射）

替代 v0.1 的固定 A-M/N-Z 谓词：

- **构造**：PRF(master_key, salt, position) 种子 → Fisher-Yates 洗牌 26 字母 → 前 13 个 → bit 0，后 13 个 → bit 1
- **逐位置独立派生**：不同位置的映射互不相关，攻击者无法跨位置统计推测映射（防合谋）
- **均匀二分**：随机文本任意位置读出的 bit ~ Bernoulli(0.5)，无水印时无统计特征
- **安全性**：无密钥者既不知道锚点位置也不知道映射 → 无法检测、移除水印，也无法**伪造指定 user_id 的水印**（防 framing）

### 10.4 可表达锚点池（零 skip 的关键）

v0.1 的教训：锚点落在无同义候选的词上 → skip → 信道错误。

v0.2 的解法：**锚点池 = "其同义组在该位置密钥映射下能表达双 bit 的词"**。

稳定性论证（为何嵌入后解码端能重建同一池）：
1. 同义替换只发生在**组内** → 词的组身份不变
2. 组对 map(pos) 的双 bit 覆盖性只依赖组内容 → 覆盖性不变
3. 词典外词永不被改 → 不进不出

正确性推论：池内锚点要么 natural（原词已对，零失真）要么 replaced（组内必有目标 bit 的词）→ **skip 严格为零**（5 个随机密钥实测验证）。

配套的词典工程：
- **稳定化**（`_build_stable_synonyms`）：跨组共享词归属唯一组 + 组内每词生成完整词条（926 词条 / 182 组）
- **单半区修补**（`_apply_group_patches`）：16 个单半区组注入跨半区补充词

### 10.5 信道编码选项

| 编码 | 码字长度 | 纠错能力 | 适用场景 |
|---|---|---|---|
| spread3（默认） | 72 bit | 每 bit 3 票多数表决，~33% 误码容忍 | 通用，抗局部改写（多票交织到全文） |
| spread5 | 120 bit | ~40% 容忍 | 高安全场景，需更长文本 |
| hamming74 | 42 bit | 每组纠 1 错（~14%） | 短文本、干净信道 |
| repeat1 | 24 bit | 无（纯 CRC 检错） | 极短文本，只判存在性 |

### 10.6 实测结果（32 项单元测试全通过）

往返与安全性（~220 词样本，spread3）：

| 场景 | 结果 |
|---|---|
| 嵌入 uid∈{0,1,42,1001,65535} → 解码 | **全部正确还原** |
| 同一文本三个用户 | 三份互异水印文本，各自解码正确 |
| 错误密钥 / 交叉盐 / 无水印原文 | 全部正确拒绝（CRC 失败） |
| 嵌入确定性（同 key+salt+uid） | 输出完全一致 |
| skip 数（多随机密钥） | 严格为 0 |

同义翻转攻击（攻击者知词典、不知锚点与映射，随机换词，20 次试验）：

| 翻转词数 | 解码成功率 |
|---|---|
| 5 | 80-100% |
| 10 | 70-95% |
| 20 | ~50% |
| 30 | ~0%（但不会解出别人的 ID） |

### 10.7 剩余限制与 v0.3 方向

1. **插入/删除导致的锚点偏移**：任何 token 数变化都会使锚点全盘失效。方向：内容寻址锚点（位置局部指纹 / n-gram 上下文哈希）
2. **paraphrase 攻击**：整句重写后同义词不复存在。方向：LLM 辅助的语义级再嵌入（重生成时保持水印约束）
3. **user_id 容量**：16 bit（65536 用户）。方向：BCH 码 + 32/64 bit
4. **词典覆盖**：自然文本词典命中率 ~50%。方向：WordNet / LLM 候选生成
5. **合谋攻击**：多个用户的文本 diff 可推测可变位置（不知道映射，但知道哪些词"被换过"）。方向：per-session 词典子集、候选噪声
6. **中文支持**：首字母谓词不适用，需要 pinyin 首字母 / 字形 / 词序谓词 + 中文同义词林

## 11. v0.3：内容寻址锚点（2026-08-18）

针对 §10.7 的头号限制（插入/删除导致锚点全盘偏移），v0.3 把锚点身份从
**位置索引**改为**局部上下文指纹**，并配套把信道模型从"固定锚点 + 交织
重复码"改为"分布式投票桶"。

### 11.1 核心机制

**稳定词 ID（替换不变的身份）**：

- 词典词 → 同义组 ID：`SHA256(sorted(group))[:10]` —— 嵌入者只在组内
  换词，组 ID 嵌入前后不变
- 词典外词 → 规范化词形 —— 这些词永不被改动

**上下文指纹（锚点身份）**：

```
fp(w) = SHA256( stable_id(左邻词) ‖ stable_id(w) ‖ stable_id(右邻词) )
```

锚点的一切密钥派生（桶分配、字母映射）都以 fp 为输入，与绝对位置无关。

**投票桶信道（取代固定锚点 + spread 码）**：

- 载荷 24 bit（16 uid + 8 CRC），L = 24 个桶，**无独立 ECC**
- 每个可锚定词位独立投票：`bucket = PRF(key, salt, fp) mod L`
  票值 = 该位词首字母在 `KeyedLetterMap(PRF(key, salt, fp))` 下的 bit
- 同桶多票 = 天然重复码；文本越长票越多，冗余随长度自动增长
- 解码：逐桶多数表决 → CRC；失败则对表决边际最小的 ≤3 桶做 chase
  翻转枚举（≤ 2³−1 次附加 CRC 试验，`chase_used` 字段暴露给上层）

### 11.2 一致性与局部性论证

**嵌入-解码一致性**（无攻击时严格成立）：
1. 嵌入替换只发生在同义组内 → 组 ID 不变 → fp 不变
2. 解码端以相同 (key, salt) 重算 fp → 桶/映射/可锚定性全部复原
3. 可锚定 ⇔ 组在该位映射下能表达双 bit → 替换永不失败（skip ≡ 0）

**编辑局部性**（对攻击的根本优势）：
- 插入/删除一个词只改变：该词自身 + 左右邻居共 ≤3 个词位的 fp
  → 最多损失 3 票（或引入 1 张随机错票），其余锚点完好
- v0.2 中同样的编辑使后续**全部**锚点偏移 → 水印尽毁

### 11.3 实验结果（30 次试验/组，262 词文本）

| 攻击 | 强度 | v0.2 存活 | v0.3 存活 |
|---|---|---|---|
| 插入 | 1 词 | 2/30 | **30/30** |
| 插入 | 10 词 | 0/30 | **30/30** |
| 插入 | 30 词 | 0/30 | 26/30 |
| 删除 | 10 词 | 0/30 | **30/30** |
| 删除 | 30 词 | 0/30 | 29/30 |
| 同义翻转 | 30 词 | 3/30 | 21/30 |
| 混合编辑 | 30 次 | 0/30 | 24/30 |

（`experiments/exp_edit_attacks.py` 可复现）

### 11.4 权衡与已知限制

- **改动率上升**：可锚定位多（105 vs 72），替换词数相应增加（54 vs 29）。
  鲁棒性换失真。方向：`anchor_rate` 参数控制投票密度
- **0 票桶**：票数 λ = N/L，N 小时可能空桶（固定输出 0）。chase 会优先
  翻转边际为 0 的桶。`min_anchorable`（默认 36）在嵌入端兜底
- **chase 误检率**：≤ 2³−1 = 7 次附加 CRC 试验 → 误检上限 ~2.7%，
  仅发生在"CRC 首轮失败"的重攻击场景；`chase_used=True` 时应降低置信度
- **指纹碰撞**：重复的 (左,组,右) 模式产生相同指纹 → 同桶同票。
  无害（等价于该桶冗余票），但降低了票间独立性
- **大窗口编辑**（整句重写）仍然致命——同 v0.2，属于 paraphrase 类攻击，
  留待 LLM 辅助再嵌入

## 12. v0.4：句子边界感知指纹 + 词典扩充 + 中文支持

### 12.1 动机

v0.3 的内容寻址锚点把水印身份绑定到局部上下文指纹 `SHA256(stable_id(left) ‖
stable_id(w) ‖ stable_id(right))`，抗插入/删除编辑。但指纹窗口**跨越句边界**
（`content.py:101-102`）——重写句子 S 后：

- S 的词全变 → S 内锚点丢失（不可避免）
- S 的首/尾词成为邻句边界词的 left/right 邻居 → 邻句边界词指纹也变 →
  邻句锚点连带丢失（可避免的附带损害）

这是 paraphrase 致命的根因。v0.4 的中心改动是把词级局部性升级为**句子级局部性**。

### 12.2 句子边界感知指纹

**改法**：加句子切分（英文 `[.!?]`，中文 `。！？；`）。句首词左邻用 `_BOS`，
句末词右邻用 `_EOS`，替代真实邻句词：

```
句首词: fp = SHA256(_BOS ‖ stable_id(w) ‖ stable_id(right))
句末词: fp = SHA256(stable_id(left) ‖ stable_id(w) ‖ _EOS)
中间词: fp = SHA256(stable_id(left) ‖ stable_id(w) ‖ stable_id(right))
```

**净效果**：重写句子 S 后，S−1 末词和 S+1 首词指纹保持原值（仍引用
`_EOS/_BOS`）→ 只损失 S 的票，邻句锚点存活。投票桶信道获得句子级局部性。

`CAConfig.sentence_aware` 开关（默认 True）控制此行为；False 回退 v0.3
跨句真实邻居行为，用于对比实验。注意：fp 值会因此开关而变，v0.3 嵌入
文本无法用 v0.4 默认解码——有意的破坏性升级。

### 12.3 词典扩充

新增 `synonym_data.py`，把英文词典从 926 词条扩充到 **2363 词条**
（621 稳定化组，3.4 扩充）。设计原则：

- 单词约束：英文词条必须单个词（无空格/连字符）
- 中文统一双字词，配合前向最大匹配分词
- 组内首字母（或声母）种类 ≥3，保证动态可锚定率
- 主词条唯一：同形词（动词/名词）只保留一个组

平均动态可锚定率 0.774（英文）/ 0.884（中文）。

### 12.4 中文支持

**LanguageAdapter 抽象**（`zh.py`）：把语言相关的四件事抽象为方法：

1. `tokenize`：文本 → token 列表（英文空格分词 / 中文前向最大匹配）
2. `normalize`：token → 词典查询键
3. `extract_symbol`：token → KeyedLetterMap 用的符号（英文首字母 / 中文声母）
4. `letter_alphabet`：KeyedLetterMap 用的字母表（英文 26 / 中文 23 声母）

`EnAdapter` 封装 v0.3 英文行为（零行为变更），`ZhAdapter` 实现中文路径。

**声母谓词**：23 个拼音声母作 KeyedLetterMap 的字母表。组内声母种类 ≥3
即可表达双 bit（动态可锚定判定）。内嵌约 450 字的声母映射表，覆盖
词典全部首字，零强依赖（jieba/pypinyin 可选）。

**分词词典**：必须包含所有组内词（主词条 + 候选词），否则替换后的候选词
（非主词条）会被拆成单字，导致 token 数变化、锚点错位。

### 12.5 paraphrase 评测

`paraphrase_sentence_attack(text, frac, rng)`：按句切分，随机选 frac 比例
句子做同义组内全词替换 + 轻度插删 + 词序微调。强度 frac ∈ {0.1, 0.25,
0.5, 0.75, 1.0} × 30 试验。

评测结果（110 锚位文本）：

| 改写比例 | v0.3 | v0.4 |
|---|---|---|
| 10% | 30/30 | 30/30 |
| 25% | 24/30 | 19/30 |
| 50% | 0/30 | 1/30 |

分析：在 110 锚位的高冗余度下，10% 改写两者都能吸收。25% 以上时被改句
票损失超过纠错能力。v0.4 的优势在理论层面（句级局部性）——当 stable_id
不因同义替换改变时，v0.3/v0.4 差异不大；当首末词跨组改变时 v0.4 显著优势。
这是诚实的结果：全文重写无法在零依赖下抵抗（理论边界）。

### 12.6 句级统计量验证

`experiments/exp_sentence_stats.py` 验证 paraphrase 后句数/句长等统计量
的保留性。结果：100% 改写时句数保留率仅 25%，句长保留率 25%。
**句级统计量保留性不足以作独立解码信道**，降级为置信度信号
（句数/句长突变提示可能遭受攻击），不合入。

### 12.7 权衡与已知限制

- **全文重写无法抵抗**：零依赖下理论边界，v0.4 只承诺部分 paraphrase 鲁棒
- **句子边界感知降低指纹强度**：句内大规模改写仍损该句全部锚点
- **中文分词歧义**：前向最大匹配可能因替换产生不同边界（已用全词
  词典缓解，但极端情况仍可能错位）
- **中文声母覆盖**：内嵌表约 450 字，覆盖词典全部首字，但文本中
  未知字仍可能返回 None（该位不可锚定，行为等同词典外词）
- **破坏性升级**：v0.3 嵌入文本需 `sentence_aware=False` 解码

## 13. v0.5：双信道签名架构（2026-08-18）

> 用户决策定案：本质是**数字签名**——防篡改 + 溯源。
> 基于 SOTA 交叉比对（见 `docs/sota_review_v0.5.md`）与实证验证。

### 13.1 架构总览

```
┌────────────────────────────────────────────────────────────────┐
│                     v0.5 签名 = 三信道冗余                       │
│                                                                │
│  信道 A: Tamper Binding（防篡改，脆而严）                        │
│    段落级 Merkle-HMAC：H_para = HMAC(K, normalize(para))        │
│    Merkle root 入链/入册。改一段 → 该段 hash 变 → root 变        │
│    可定位篡改段落。语义不变的重排 → 段序 Merkle 可检测           │
│                                                                │
│  信道 B: Provenance Recovery（溯源，鲁棒而松）★v0.5 核心        │
│    密钥派生绿名单 × 16 频带统计，承载 16-bit UID                 │
│    ⟨v(text), τ_uid⟩ 内积形式：v = 逐带绿计数向量                 │
│                              τ = ±1 方向向量（UID 位映射）       │
│    B1 文本无关派生（已验证）；B2 PostMark 式文本相关（可选路由）  │
│                                                                │
│  信道 C: v0.3/v0.4 投票桶（保留，不丢弃）                        │
│    位置锚定 24-bit payload + CRC + chase                        │
│    未编辑文本上强；与 B 互为备份                                 │
└────────────────────────────────────────────────────────────────┘
```

### 13.2 信道 B 机制（已实证验证）

**嵌入**：
1. 词典预处理：**不相交划分**（同义词组重叠率 23%，必须先到先得去重）
   + **可翻转组过滤**（剔除单色组 179/664，组内全同色无法编码）
2. 密钥 `K` 派生：`green(w) = HMAC(K, w)[0] >> 7`；`band(h) = HMAC(K‖band‖, h) % 16`
3. UID 16 bit ↔ 16 频带方向：`bits[b] = (uid >> b) & 1`
4. post-hoc 同义替换：词 w ∈ 组 g ∈ 带 b → 替换为组内颜色 = `bits[b]` 的候选

**检测**：
1. 逐带统计词典词绿占比 `ĝ(b)`
2. **逐带 p0 标定**（2009 零水印移植核心教训：p0 ≠ 0.5，
   实测带间 p0 ∈ [0.411, 0.535]）：
   `z_b = (ĝ(b)·n_b − p0(b)·n_b) / √(p0(b)(1−p0(b))n_b)`
3. `uid = Σ (z_b > 0) << b`
4. 存在性得分 = `Σ|z_b|`（对比无水印 null 分布）

### 13.3 实证结果（模拟文本，600-1000 词，6 UID × 3 试）

| 工作点 | 往返 | 30% 改写 | 50% 改写 | 70% 改写 |
|---|---|---|---|---|
| 400 词 bias=1.0 | 83% | 83% | 56% | 6% |
| **600 词 bias=1.0** | **100%** | **100%** | **89%** | 17% |
| **1000 词 bias=1.0** | **100%** | **100%** | 89-100% | 67% |
| 600 词 bias=0.9 | 94% | 94% | 61% | 6% |

存在性检验（Σ|z|，800 词，50 试）：
- 无水印 median=40.6，有水印 median=88.3 → 未编辑文本 FPR≈2%, TPR=100%
- **30% 改写后得分 62.6 仍高于无水印；50% 改写 45.5 与 null 重叠**

**关键规律：解码鲁棒性 > 存在性鲁棒性**
（50% 改写时 UID 解码仍 89%，因解码只需 z 符号一致；存在性需 z 幅值，
衰减更快）。部署策略：**UID 注册库匹配**（同 2009 IPR 思路）优于盲检。

### 13.4 踩坑记录（移植 2009 论文的三个必修课）

1. **同义词组重叠 23%** → 词的多带归属冲突 → 必须不相交划分（先到先得）
2. **单色组 27%**（677 组中 179 组全同色 + 13 组交集）→ 无法编码且污染
   null → 必须过滤出 485 个可翻转组
3. **p0 ≠ 0.5** → 逐带标定是 2009 论文"结合常用字频率表"的直接对应，
   跳过这步 z 检验系统性偏移（未嵌文本 z=-2.4 的假信号）

### 13.5 中文路线（纪昀移植，待实现）

中文 260 组双字词同机制：`green(w) = HMAC(K‖zh‖, w)`（词级，非声母级），
`band(h) = HMAC(K‖zhband‖, h) % 16`。初步验证（未做不相交+标定修复）：
0x5678 → 0x5668（1 bit 错），30% 改写 0 汉明距。套用 13.4 三个修复后
预计达英文同等水平。

### 13.6 与投票桶（信道 C）的协同

- B 检测出 UID + C 解码一致 → 高置信（文本未编辑或轻编辑）
- B 出 UID + C 失败 → 已被 paraphrase，B 单独溯源
- C 成功 + B 弱 → 局部编辑（C 锚点未受损段）
- A root 不匹配 + B 出 UID → 篡改确认 + 溯源归属双证据

### 13.8 检测层语言无关性判别实验（2026-08-18）

> 问题来源：绿名单/频带锚定在"词法单元"上（英文 word / 中文双字词），
> 是否必须为每种语言分别设计？能否下沉到 token/字节/字符层做到语言无关？

**实验设计**（`experiments/exp_token_layer.py` + `exp_layer_diagnose.py`）：
嵌入固定为词层 16 带同义替换（密钥派生），检测端对比四种层：
词层（语言相关，baseline）/ UTF-8 字节层 / Unicode 字符层 / 字符 bigram 层。
后三种理论上语言无关（同一检测器跑英文和中文）。

**表面结果**：英文 800 词，字节层 |z| 无水印 0.90 → 有水印 7.01，30%/50%
改写后仍 6.9，看似是理想的语言无关信道。**但判别实验揭示这是伪信号**：

| 判别实验 | 结果 | 含义 |
|---|---|---|
| 词典绿/红半区字节绿率 | 差 -0.013（无差异） | 信号不来自词典颜色投影 |
| 自有 key 字节层 p0 | **0.7444**（≠0.5） | p0 强依赖 key×文本风格 |
| 全部 UID 的 z 方向 | 恒为负（-5~-10），不跟 UID | z 跟"是否换词"走，不跟水印内容走 |
| 错误 key 检测 | z 归零（±1） | **信号不绑定密钥** |
| 无密钥第三方随机改写 100% | **z = -7.29** | 任何人改写都触发检测 → 无鉴别力 |

**机制**：同义替换把功能词换成实义词（或反之），改变字节频率分布；
字节层 z 测到的是"文本被改写过"的风格伪影，与密钥无关。
中文等长双字词替换伪影小（z=1.93），英文变长替换伪影大（z=7）。

**结论（三条）**：
1. **语义信道必须锚定在语言语义单元上，这是本质不是缺陷**。
   水印信号 = 密钥派生的"同义候选颜色选择"，颜色绑定词身份，
   任何脱离语义单元的表层（字节/字符/bigram/subword token）
   只能看到改写痕迹，看不到密钥信号。判别实验实锤。
2. **语言差异已隔离在 adapter 层，统计信道 100% 共享**。
   "中文双字词"与"英文 word"是同一抽象（多字符语义等价单元）的两个实例。
   加第三语言 = 新 adapter + 词典，核心算法（16 带 z 检验/p0 标定/存在性
   得分）零改动。不是"两套方案"，是"一套方案 + 语言资源包"。
3. **tokenizer 依赖是额外部署负担**：tiktoken BPE 表下载在受限网络即失败
   （实测），且不同模型 tokenizer 不互通 → token 层引入模型生态绑定，
   违背零依赖原则。真正的语言无关出路是上浮到 embedding 层（PostMark
   路线），但那是用模型依赖换语言无关，与已选路线冲突。

**架构含义**：v0.5 维持"嵌入语言相关（adapter + 词典）+ 检测共享核心
（绿名单/频带/z 检验）"。LanguageAdapter 是唯一语言相关的接缝。
