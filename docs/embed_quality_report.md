# 嵌入文本质量量化报告（v0.15）

> **时间**：2026-09-11
> **脚本**：`experiments/exp_embed_quality.py`（fixed seed，可复现）
> **原始数据**：`experiments/embed_quality_result.json`
> **限制声明**：沙箱无 LLM/困惑度模型，本报告用**可离线计算的客观代理
> 指标**；"零感"的最终判据（PPL 差、人工盲评）列为后续工作，本报告
> 不把代理指标冒充终判。

## 一、指标与实测（zero_cost 中文，demo 语料 5 篇长文）

| 指标 | 随机选择 | 搭配打分选择 |
|---|---|---|
| 替换率（被改 token / 词典命中） | 34.5% | 34.5% |
| 邻居兼容率（语料左/右邻居匹配） | 79.1% | 79.1% |
| 15% 同义攻击后 UID 还原 | 1/5 | 1/5 |

## 二、三个发现

### 发现 1：零感词典下同义选择是"被密钥和 UID 决定的"，不是随机的

136 组零感词典绝大多数是 2 词组（一绿一红）：目标 bit 一旦确定，
候选池里只剩**唯一**成员——换哪个词由密钥+UID 完全决定，打分器
无自由度可发挥（本实验随机/打分两组输出逐字节相同，即此因）。

**质量含义**：zero_cost 模式下 ~21% 的强制替换落在语料邻居集之外
（邻居兼容率 79.1%），这是"零感"的真实代价面，且**无法靠选词策略
改善**——颜色约束锁死了选择。

### 发现 2：打分器对 default/hybrid 模式有效（已验证生效）

default 全词林 18,896 组中 18,814 组有 ≥3 成员（目标色候选 ≥2），
打分器在这些组上改变选择（输出差异已验证）。calibrate_corpus 可用
时 facade 自动装配（中文路径），`EmbedResult.choice_scorer_used` 标记。

### 发现 3：质量-鲁棒性的真实权衡点在"跳过多病句位"

打分器救不了强制替换，但 embed 可以在"唯一候选的邻居兼容度为 0"
时**跳过该位置**（牺牲一点容量换病句率）。本版未实现（改动编码
密度语义，需要配套容量文档更新），列为 v0.16 候选。

## 三、15% 同义攻击下 UID 还原 1/5 的解读

组内随机替换是**最强模型感知攻击**（攻击者也在同义组内选词，每次
替换以 ~50% 概率翻转该带颜色）。1/5 与 ai_text_judgment_report 的
syn40 归因弃权结论一致：该类攻击下本方案**只承诺存在性，不承诺
归因**（README 边界表已如此声明）。
