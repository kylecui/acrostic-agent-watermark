## 二、五个硬结论

### 结论 1：null 模型是域特定的，跨域标定比不标定更糟

用 demo（技术散文）标定的阈值放到红楼梦/英文小说上，FPR 反而升到
19–53%（未标定只有 0–2.5%）。z 得分的零分布由**用词习惯**决定，
技术散文的"正常波动"和古典文学的"正常波动"不是一个分布。

**部署铁律：标定语料必须与待检测文本同域。** 跨域标定是负资产。

### 结论 2：域内标定有效——FPR 压到 0–7%，TPR 70–100%

同域前半拟合、后半测试的教科书式部署，全部域 FPR ≤ 6.7%（小样本
域除外），TPR 70–100%。统计水印的可用性前提是**域内标定**，这一点
从猜测变成了实测。

### 结论 3：未标定默认常数是保守的——FPR 低但 TPR 也低

默认 `0.7 + 1.35·m` 在域外文本上几乎不误报（0–2.5%），但检出率
在英文小说（3.3%）和短块（16%）上不可用。**开箱状态只适合域内
技术长文**；其他场景要么标定、要么接受"检出率低"。

### 结论 4：英文文学不在 zero_cost 词典的能力窗口内

英文零感词典（133 组拼写变体+副词）对古典小说命中极稀疏 → 每篇
活动带 1–3 个、每带 1–2 词，未标定 TPR 3.3%。这是词典覆盖问题，
不是统计问题；英文生产场景要么用 default/hybrid 全词林，要么用
AI 生成文本（零感词密度高，正是该词典的设计目标）。

### 结论 5：重复模板文是存在性检测的结构性对手

"短句复制 + 零感词饱和"的文本（表单信、模板回复、刷量内容）在
所有未标定/跨域配置下 FPR 79–100%，**且未标定下 28.3% 会被误归因
到具体用户**（文本的真实统计特征与随机候选方向对齐，abstain 协议
救不回来）。只有域内标定能压到 0。

缓解路径（按有效性排序）：
1. **域内标定**（本报告实测唯一有效）
2. v0.15 已落地的 PER_WORD_CAP=3 去相关（v0.14 前同一文本 Σ|z| 高
   达 12.65 且无界；现封顶 3.46）——把滥用压到有界，但不能替代标定
3. 业务层过滤：扫描前剔除高度重复的模板文（相似度 >0.9 直接跳过
   水印判定，走人工）

## 三、对 README 场景表的修正

README「适用场景」表的「标定 + ≥1200 字检出 90–100%」须加两个
限定（已同步进 README）：
- **标定必须域内**（跨域标定实测 FPR 19–53%，比不标定差）
- 90–100% 是域内长文 + 域内标定的联合条件；域外/未标定的实测数字
  以本报告为准
